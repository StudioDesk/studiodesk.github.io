How it works

From idea to done, with a second opinion built in

Say what you want in plain words. The team takes it from there, and comes back to you for the calls that matter.

  1. Your idea

    In your own words, with any files it needs.

  2. A plan

    Stories for code, steps for everything else.

  3. You say go

    Every plan waits for you, unless your house rules say otherwise.

  4. The work

    Each agent in a copy of its own.

  5. Tested and reviewed

    Code is tested in a sandbox, then an agent that didn't make it reviews the result.

  6. Done

    Merged into your branch, or ready to read.

  7. Sent backNot good enough? It goes back with the findings, and the retry remembers them.

Get started

Running in a few minutes

A new install opens with two samples, a small code library and a writing brief for a community garden, each with a team and ideas to send. They run for real, on your own sign-in.

What you need

  • Windows 10 or 11
  • Node.js 24 or later
  • Claude Code or Codex CLI, signed in with a subscription rather than an API key. One is enough.
  • Git, for code projects
  • An administrator, once, to set up the test sandbox from Settings

Four steps

  1. Download the release and extract it somewhere you'll keep it
  2. npm ci once, in that folder
  3. npm start or double-click start-studio.cmd
  4. Open http://127.0.0.1:4317 in Chrome or Edge

Ready for your own code? Point Studio desk at a git repository and it works out what may change, what's protected and where the tests are, then runs them once before it starts. Not code? Start a project without a folder.

Questions you might have

The short answers

What does it cost?

Studio desk is free and open source under the MIT license. The AI work runs on your Claude Code or Codex CLI subscription, so there are no API keys and no per-request bills.

What runs where?

Studio desk itself runs on your computer: the controller, the dashboard and your data, which lives in the data folder next to the app. It has no cloud or hosting of its own. The AI work goes through your Claude Code or Codex CLI, signed in with your subscription. To back up, stop the controller and copy the folder.

How safe is it?

Agents run commands on your computer through your CLI, so the CLI and the commands you approve matter. Codex CLI runs in its own sandbox. Claude Code has no sandbox on Windows and runs only the commands you approve, unless you turn on auto mode; approved commands apply to every project and agent, so approve narrowly. A change's tests are kept apart: they run in a disposable copy inside the built-in sandbox, as a separate Windows account that can change only that copy and can't reach past your computer. Agents never change your AGENTS.md, CLAUDE.md, package.json, lockfile or tool configuration, and deleting a project never changes your files or branches. Each tested change leaves a marker under refs/studio/ in your repository.

Does it push my code anywhere?

No. It commits locally, and when your work goes to a remote is up to you. Pushing, confirmed every time, is coming with releases.

What does a code project need?

A git repository with a clean working tree, and tests that run with Node's test runner (node --test), or no tests yet. Type checks, builds and anything that needs installed packages should be part of the tests.

Does it work on a Mac or Linux?

Windows 10 and 11 are tested today. Linux and macOS are being tested for an upcoming release.

Can it do several things at once?

Each agent works on one thing at a time. Steps of other work run side by side when different agents are free; a code project's stories go one after another for now.

What happens when I hit a usage limit?

Work pauses and picks up again on its own when the limit resets. It doesn't count as something that needs you; it sorts itself out.

Is it only for code?

No. It works on code in your git repositories and on anything else you can describe, like writing. Work that isn't code needs no folder at all.
