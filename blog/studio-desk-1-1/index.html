Studio desk 1.1: from "it's merged" to "it's shipped"

Studio desk 1.0 put a team on your idea: a planner, agents who build it, tests and a reviewer who signs off. 1.1 takes the work the rest of the way, into releases people can run, with fixes that reach everyone and a reviewer that actually looks at what it built.

November 2, 2026·3 min read

Ship in releases

Merged isn't shipped. Somebody still has to decide what goes into the next version, write the notes, bump the number, tag it and push it, and somebody has to make sure the fix for last month's version doesn't get lost on the way.

Now you send ideas to a release. A milestone like 1.2.0 gathers what you send it. When it's done, press Release: the planner drafts the notes for you to approve, the version is bumped, the tests run on the release itself and it's tagged. Anything unfinished moves to the next milestone if you like, so nothing ships half-done.

Need to fix something people already run? Open a patch milestone like 1.1.1. Studio desk makes a release line from that version's tag, lands the fix there and carries it up to every newer line, so nobody loses it when they upgrade. And Push sends a released line and its tag to your remote, with your own git sign-in. It asks every time.

More done at once

In 1.0, a code project's stories went one after another. Now they build side by side, and an agent can work on several things at once, up to the limit you set.

Side by side means two changes can touch the same lines. When a story runs into work that landed while it was being built, its change is merged onto the latest code and its agent resolves the overlap, keeping what it already built. Its tests and a fresh review follow before it goes in. You only hear about it if the same story conflicts twice.

A reviewer that looks

Tests and code review catch a lot, but not a button that's in the wrong place. Now, before a story's review, the pages it names are photographed at desktop and phone widths, in light and dark, and the reviewer has to describe every picture before the story can pass. If the page doesn't match, it goes back.

Want to look yourself? Try the change in a copy of your own before it lands.

Agents that ask

Some calls aren't an agent's to make. Now an agent stops and asks you, with its options and the one it recommends, and picks up from its saved work once you answer. And before any work starts, you can reply to the planner's plan and talk it through, then make it official when it's right.

A library your team follows

Every project now has a library: files like a brand guide or a spec that every later step reads, with their history. The Artifacts page shows what the work made, read in place, and a snapshot bundles a set of files to download whenever you want to hand them off.

Runs in more places

Studio desk now runs on macOS and Linux as well as Windows, with the built-in test sandbox on all three. And it signs you in: open the link the controller prints once, and your browser stays signed in. Other programs on your computer, a change's tests included, can't act as you.

Good to know

Upgrading keeps your projects, agents and history as they are, and release lines are opt-in: nothing changes for a project until you give it a milestone. Tests still run with Node's test runner. Pictures of a story's pages, and trying a change inside the sandbox, work on Windows only for now. Claude Code has no sandbox on Windows, so approve its commands narrowly. macOS and Linux have had less use than Windows.

Try it

Studio desk is free and open source, and it runs on the Claude Code or Codex CLI subscription you already have. No API keys, no per-request bills, and it all stays on your computer.

Download the latest release from github.com/studiodesk/studio-desk (or clone the repository and check out v1.1.0), run npm ci once, then npm start, and open the link the controller prints, as the README shows. Already on 1.0? Stop the controller, keep a copy of your data folder, update, and open the new link once.

You bring the ideas. Studio desk brings the team.
