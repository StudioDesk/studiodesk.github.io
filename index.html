How it works

From idea to done

Describe what you want in plain words. Then the team takes it from there.

  1. A planner turns your idea into work

    Stories for code, steps for everything else.

  2. You approve the plan

    Every project starts on house rules where every plan waits for you.

  3. Agents do the work

    Each in a copy of its own.

  4. Checks run your tests

    On every code change, in a sandbox.

  5. A reviewer signs off

    Or sends back anything that falls short to be fixed. Retries remember what went wrong last time.

  6. It goes in

    Code is merged into your branch; other work is ready for you to read.

Here's how a run can go. You send the code sample an idea for its small library. The planner splits it into two stories, and you approve the plan. An agent makes the first change in its own copy and the tests run. The reviewer finds something that falls short and sends it back. The retry knows what went wrong, the fix passes its tests and review, and the change is merged into your branch. Then the second story starts.

Why you'll like it

A team that checks its own work, and answers to you

And it isn't only code: writing and other work get planned, done and reviewed, step by step.

It checks its own work

Every change is tested and independently reviewed before it lands. Work that falls short goes back to be fixed. What reaches your branch has already passed its tests and a review. The tests run in a built-in sandbox, as a separate Windows account that can change only the copy being tested and can't reach past your computer.

Nothing happens behind your back

Every step every agent takes is on the record, down to the commands it ran and why anything stopped. Read every change with its tests and reviews, or open any attempt to see exactly what an agent did and said. When something stops, you know why and what to do about it.

You make the calls

When something needs you, like approving a plan or accepting a result, it shows up in plain words with what to do next. House rules decide how much needs you, and you can turn that up or down any time.

Your team, your way

Choose who's on each project's team, which AI tool and model each agent uses, and what they're told. Need a specialist, like a copywriter? Make one just for that project.

It runs on what you already pay for

Your Claude Code or Codex CLI subscription. No API keys, no per-request bills. And it stays on your computer: no cloud, no hosting.

Get started

Try it in a minute

A new install opens with two samples, a small code library with its tests and a writing brief for a community garden's new volunteers, each with a team and a few ideas to send. They run for real on your own sign-in.

What you need

  • Windows 10 or 11
  • Node.js 24 or later
  • Claude Code or Codex CLI, signed in with a subscription rather than an API key. One is enough.
  • Git, for code projects
  • An administrator, once, when you set up the test sandbox from Settings

Four steps

  1. Download the release and extract it somewhere you'll keep it
  2. npm ci once, in that folder
  3. npm start or double-click start-studio.cmd
  4. Open http://127.0.0.1:4317 in Chrome or Edge

Ready for your own code? Point Studio desk at a git repository and it works out what stories may change, what's protected and where the tests are. It runs your tests once before it starts, and adds the project only if they pass. Not code? Start a project without a folder.

Good to know before you start

What Studio desk 1.0 does and doesn't do yet

  • Only Windows 10 and 11 have been tested. macOS and Linux haven't been tested.
  • Claude Code has no sandbox on Windows. The built-in sandbox covers your tests, not the agents. Claude Code runs only the commands you approve, unless you turn on auto mode, which lets Claude Code decide. Codex CLI runs in its own sandbox. Anything an agent runs has your account's access to your files and network, so approve narrowly.
  • Code projects need a git repository with a clean working tree, and tests that run with Node's test runner (node --test), or no tests yet. Type checks, builds and anything that needs installed packages should be part of the tests.
  • Each agent works on one thing at a time. A code project's stories go one after another; other work can run steps side by side when different agents are free.
  • It commits locally and never pushes. When your work goes to a remote is up to you.
  • Nothing is checked by eye. Reviews read the code, tests and evidence, not what's on screen.
Questions you might have

The short answers

What does it cost?

Studio desk is free and open source under the MIT license. The AI work runs on your Claude Code or Codex CLI subscription, so there are no API keys and no per-request bills.

What runs where?

Studio desk itself runs on your computer: the controller, the dashboard and your data, which lives in the data folder next to the app. It has no cloud or hosting of its own. The AI work goes through your Claude Code or Codex CLI, signed in with your subscription. To back up, stop the controller and copy the folder.

How safe is it?

Agents run commands on your computer through your CLI, so the CLI and the commands you approve matter. Codex CLI runs in its own sandbox. Claude Code has no sandbox on Windows and runs only the commands you approve, unless you turn on auto mode. Approved commands apply to every project and agent, so approve narrowly. A change's tests are kept apart: they run in a disposable copy inside the built-in sandbox, as a separate Windows account that can change only that copy and can't reach past your computer. Agents never change your AGENTS.md, CLAUDE.md, package.json, lockfile or tool configuration, nothing is pushed, and deleting a project never changes your files or branches. Each tested change does leave a marker under refs/studio/ in your repository, and those stay after a project is deleted.

Does it work on a Mac?

Not yet tested. Only Windows 10 and 11 have been tested so far; macOS and Linux haven't.

What happens when I hit a usage limit?

Work pauses and picks up again on its own when the limit resets. It doesn't count as something that needs you; it sorts itself out.

What if I close it in the middle of a task?

Close the controller any time. Anything cut off mid-step waits for you to check it, and nothing is replayed blindly.

Is it only for code?

No. It works on code in your git repositories and on anything else you can describe, like writing. Work that isn't code needs no folder at all.
