Studio desk 1.0: stop babysitting one agent and put a team on it

Hand an idea to a team of AI agents and get back work that's been planned, built, tested and reviewed, on the Claude Code or Codex CLI subscription you already have, with you making the calls.

October 27, 2026·4 min read

You know the routine. You give one agent in one terminal a task, and then you sit with it. You watch it run. You scroll back to find out what it changed. When it stops, you guess why. And when it says it's done, the checking is still your job.

Studio desk 1.0 is out, and it works differently. You bring the ideas. Studio desk brings the team.

I built it because today's AI agents are powerful, but once a few of them are working, it's easy to lose track of the work and of what's actually happening. Studio desk keeps all of it in one dashboard, so you're not swapping between terminal tabs to find out.

A team, not a terminal

Describe what you want in plain words. Every project has a team, and every team has roles:

  • a planner who turns your idea into stories or steps,
  • agents who do the work, each in a copy of its own,
  • checks that run your tests,
  • a reviewer who signs off, or sends the work back.

You choose who's on the team, which AI tool and model each agent uses, and what they're told. A new install comes with a starting team, so you can send your first idea right away. When a project needs a specialist, like a copywriter or a designer, make one just for that project: it never touches the agents your other projects rely on.

It checks its own work

Say you point Studio desk at a repository and ask for a new option in a small library. The planner breaks the idea into stories, and you approve the plan. An agent builds the first story in its own copy, and your tests run. The reviewer reads the change, the tests and the evidence, finds a case the tests don't cover, and sends it back. The retry starts from what went wrong last time, fixes it, passes review, and the change is merged into your branch.

That's the rule, not the exception: every change is tested and independently reviewed before it lands, and work that falls short goes back to be fixed. The tests run in a built-in sandbox, as a separate Windows account that can change only the copy being tested and can't reach past your computer. Before it takes on your repository at all, Studio desk runs your tests once and adds the project only if they pass. It commits locally and never pushes.

Nothing happens behind your back

Every step every agent takes is on the record, down to the commands it ran and why anything stopped. Read every change with its tests and reviews, or open any attempt to see exactly what an agent did and said.

When your CLI hits its usage limit, work pauses and picks up again when the limit resets. Close the controller any time: anything cut off mid-step waits for you to check it, and nothing is replayed blindly.

You stay in charge

When something needs you, like approving a plan or accepting a result, it shows up on the project's Today page in plain words, with what to do next. Everything else, like waiting for a busy agent, sorts itself out.

House rules decide how much needs you. Every project starts on the recommended ones: you approve every plan, and work that passes its tests and review goes in on its own. Turn that up or down any time.

On what you already pay for, on your computer

Studio desk is open source under the MIT license, and it runs your agents through your Claude Code or Codex CLI, signed in with a subscription rather than an API key. No API keys, no per-request bills. It stays on your computer: no cloud, no hosting, and everything lives in the data folder next to the app.

Not only code

Writing and other work get planned, done and reviewed step by step, the same way, and need no folder. To see both kinds first, Studio desk opens with two samples, a small code library with its tests and a writing brief, each with a team and ideas to send.

What it needs, and what's still rough

This is a 1.0, and you should know where the edges are:

  • Windows 10 or 11 only, for now. macOS and Linux haven't been tested.
  • You'll need Node.js 24 or later, Claude Code or Codex CLI signed in with a subscription, and Git for code projects. The test sandbox needs a one-time setup from Settings, where Windows asks for an administrator.
  • Code projects need a git repository with a clean working tree and tests that run with Node's test runner (node --test), or no tests yet.
  • Claude Code has no sandbox on Windows. The built-in sandbox covers your tests, not the agents. Claude Code runs only the commands you approve in Settings, unless you turn on auto mode, which lets Claude Code decide; Codex CLI runs in its own sandbox. Anything an agent runs has your account's access to your files and network, so approve narrowly.
  • One thing at a time. Each agent works on one thing at a time, and a code project's stories go one after another.
  • Nothing is checked by eye. Reviews read the code, tests and evidence, not what's on screen.

Planned: stories running side by side within a project, a model router across your connected CLIs, and an installer.

Try it

Download the latest release from github.com/studiodesk/studio-desk (or clone the repository and check out v1.0.1), run npm ci once, then npm start, and open the dashboard as the README shows. Pick a sample or bring your own repository, send an idea, and approve the plan.

You bring the ideas. Studio desk brings the team.
